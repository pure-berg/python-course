# Python-разработчик за 8 недель: от базы до первой работы

Практический курс с автопроверкой задач. Цель — к концу 8-й недели уверенно проходить собеседования на **Junior Python Backend Developer** и иметь портфолио из проектов, которые не стыдно показать.

## Честно перед стартом
- **8 недель — это интенсив**: ~5 часов в день, 6 дней в неделю (≈ 250 часов). Если получается 2–3 часа в день — иди по тому же плану, но растяни на 3–4 месяца. Это лучше, чем пропускать темы.
- Курс доводит до уровня «готов к собеседованиям». Сам поиск работы обычно занимает ещё от нескольких недель до нескольких месяцев — поэтому отклики начинаются уже на 7-й неделе, а не после курса.
- Учит не чтение, а **решение задач руками**. Теории ровно столько, сколько нужно, чтобы решить задачи.

## С чего начать
1. Пройди **[входной тест](00-placement-test/README.md)** (~1,5 часа) — он скажет, с какой недели стартовать.
2. Запиши результат в раздел [Прогресс](#прогресс) ниже.
3. Открой README своей недели и иди по дням.

## Как устроены задачи
В каждой неделе 1–6 есть файл с заготовками (`week01.py`, `queries.py`, `app.py`…). Каждая задача — функция или класс с описанием и примерами, внутри `raise NotImplementedError`. Ты заменяешь его своим решением и запускаешь тесты:

```bash
pytest week-01-basics          # одна неделя
pytest                         # весь курс
pytest week-01-basics -k caesar   # одна задача
```

В конце печатается прогресс:
```
week-01-basics                 ██████░░░░   9/14   ✗ ошибок: 1   … не начато: 4
```
- **не начато** — задача ещё с `NotImplementedError`;
- **ошибок** — решение есть, но неверное: читай, что пишет тест.

После каждого `git push` те же тесты запускает GitHub Actions (вкладка **Actions**): зелёная галочка — всё, что начато, решено верно.

## Как работать с любого устройства

| Где | Как | Для чего |
|---|---|---|
| **Свой компьютер** (основной вариант) | `git clone https://github.com/pure-berg/python-course.git`, затем `cd python-course && python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt` | вся учёба, без ограничений |
| **Любой браузер, без установки** | на странице репозитория: зелёная кнопка **Code → Codespaces → Create codespace on main**. Откроется VS Code в браузере, всё уже установлено | когда не за своим компьютером |
| **Быстро поправить файл** | нажми клавишу `.` на странице репозитория (откроется github.dev) | правки без запуска кода, бесплатно и без лимитов |
| **Телефон** | приложение GitHub или браузер | читать теорию и задачи, смотреть статус проверок |

⚠️ У Codespaces бесплатный лимит — порядка 60 часов в месяц на базовой машине (актуальное — в Settings → Billing). Для 5 часов в день этого не хватит, поэтому основное место работы — свой компьютер, а Codespaces — запасной вариант. Codespace сам засыпает через 30 минут бездействия; закончив, лучше остановить его вручную (Code → Codespaces → … → Stop).

Не забывай синхронизироваться: в начале работы `git pull`, в конце — `git add . && git commit -m "неделя 1: задачи 1-5" && git push`.

## Распорядок дня (недели 1–7)
- **~30 мин** — повтор вчерашнего: перерешай по памяти одну вчерашнюю задачу.
- **~1,5 ч** — теория по плану дня (читать + сразу пробовать в консоли).
- **~2,5 ч** — задачи / проект.
- **~30 мин** — 1 задача LeetCode (с недели 4), коммит, отметить прогресс.

## Правила
1. **Сначала сам.** Застрял на 20 минут — перечитай теорию, напиши маленький эксперимент. Ещё 20 минут — спроси подсказку (не решение).
2. **Код каждый день.** Лучше 2 часа ежедневно, чем 10 часов в субботу.
3. **Коммит каждый день.** Зелёная сетка активности на GitHub работодатели тоже видят.
4. **Не застревай на перфекционизме.** Неделя закончилась — переходи дальше, хвосты добивай в 7-й день.
5. **Объясняй вслух.** Если не можешь объяснить решение — не понял его. На собеседовании спросят именно так.
6. Про ИИ-помощников — см. [RESOURCES.md](RESOURCES.md#как-пользоваться-ии-chatgpt-claude-и-тп-во-время-учёбы).
