# Неделя 6. HTTP, REST, FastAPI — и главный проект портфолио

**Цель недели:** понимать, как работает веб; написать REST API на FastAPI с валидацией и тестами; начать **проект №2** — бэкенд-сервис с БД и авторизацией, который будешь показывать работодателю.

## План по дням

### День 1 — как работает веб
- [ ] HTTP: запрос/ответ, методы (GET, POST, PUT, PATCH, DELETE), заголовки, тело, коды ответа (2xx/3xx/4xx/5xx), идемпотентность.
- [ ] REST: ресурсы, URL вида `/users/42/orders`, что такое stateless.
- [ ] JSON, `curl -i`, `curl -X POST -H "Content-Type: application/json" -d '{...}'`.
- [ ] Python-клиент: `httpx` (или `requests`) — сходи в публичный API (например, `https://api.github.com/users/<ник>`), разбери ответ.
- [ ] Что происходит, когда вводишь URL в браузер (DNS, TCP, TLS, HTTP) — **классический вопрос на собеседовании**.

### День 2–3 — FastAPI: учебное API задач (с автотестами)
- [ ] Пройди [официальный туториал FastAPI](https://fastapi.tiangolo.com/tutorial/) до разделов про Dependencies включительно.
- [ ] Pydantic v2: модели, `Field(min_length=..., ge=..., le=...)`, `model_dump(exclude_unset=True)`.
- [ ] Реализуй API по спецификации ниже в [app.py](app.py). Проверка: `pytest week-06-web-fastapi`.
- [ ] Запусти руками: `fastapi dev week-06-web-fastapi/app.py` (или `uvicorn app:app --reload` из папки) и открой `/docs` — Swagger UI генерируется сам.

**Спецификация учебного API (хранение — в памяти):**

| Метод и путь | Что делает | Ответ |
|---|---|---|
| `GET /health` | проверка живости | `200 {"status": "ok"}` |
| `POST /tasks` | создать задачу. Тело: `title` (строка 1–200 символов, обязательно), `description` (строка или null, по умолчанию null), `priority` (целое 1–5, по умолчанию 3) | `201` + задача |
| `GET /tasks` | список задач по возрастанию `id`; необязательный фильтр `?done=true/false` | `200` + список |
| `GET /tasks/{id}` | одна задача | `200` или `404 {"detail": "Task not found"}` |
| `PATCH /tasks/{id}` | частичное обновление любых полей: `title`, `description`, `priority`, `done` | `200` + задача, `404`, `422` при невалидных данных |
| `DELETE /tasks/{id}` | удалить | `204` без тела или `404` |

Задача в ответе: `{"id": 1, "title": "...", "description": null, "priority": 3, "done": false}`. id начинаются с 1 и не переиспользуются после удаления.
Невалидные данные → `422` (FastAPI сделает сам, если правильно описать Pydantic-модели).

### День 4 — проект №2: старт
Новый публичный репозиторий. Тема — на выбор (или своя, сопоставимая по объёму):
- **Трекер привычек**: пользователи, привычки, отметки выполнения, статистика серий (streak);
- **Бронирование переговорок**: комнаты, слоты, бронирования без пересечений по времени;
- **Мини-маркетплейс**: товары, корзина, заказы со статусами (можно переиспользовать SQL недели 5).

Сегодня: структура проекта (`app/api`, `app/models`, `app/schemas`, `app/services`, `tests/`), `docker-compose.yml` с Postgres, SQLAlchemy 2.0 + **Alembic** (миграции), первые CRUD-эндпоинты.

### День 5 — авторизация
- [ ] Регистрация и логин, хеширование паролей (`passlib[bcrypt]` или `pwdlib`), **JWT** (`pyjwt`), зависимость `get_current_user`.
- [ ] Пользователь видит и меняет только свои данные (проверь тестом, что чужое → 403/404).
- [ ] Настройки через переменные окружения (`pydantic-settings`), секреты — в `.env`, `.env` — в `.gitignore`, в репо — `.env.example`.

### День 6 — тесты проекта
- [ ] pytest + `TestClient`, отдельная тестовая БД, фикстуры (клиент, пользователь, токен).
- [ ] Покрыть: успешные сценарии, 401/403/404/422, бизнес-правила (например, пересечение броней).
- [ ] `pytest --cov` (пакет `pytest-cov`): цель ≥ 70%.
